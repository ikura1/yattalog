# 004. v1 は個人用、共有は将来に備える

- 日付：2026-10-10
- 状態：決定

## 背景
家族や同居人とイベントを共有し、「誰が最後にやったか」まで分かるようにしたいという将来像がある。
一方で、共有機能を最初から入れると、権限・招待・通知などの設計が大きく膨らむ。

## 決定
- v1 は個人用として作り、共有機能は実装しない
- ただしデータモデルは、後から共有を追加できる形にしておく
  - 方針案：イベントの持ち主を「ユーザー」ではなく、ユーザーごとに1つ自動で作る「スペース」にする。将来、スペースにメンバーを追加できるようにすれば共有になる
  - 記録には、誰が記録したかを v1 から保存しておく
- 具体的なモデルはステップ4で決める

## 理由
後から「持ち主」の概念を差し替えると、データ移行と全クエリの見直しが必要になり、コストが大きい。
最初から間に1層挟んでおけば、v1 ではほとんど負担にならない。

## 影響・トレードオフ
- v1 では、スペースが画面に出てくることはない（ユーザーには見えない内部の概念）
- 権限チェックは「スペースのメンバーかどうか」で統一する
