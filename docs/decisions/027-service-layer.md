# 027. 処理はサービス層にまとめ、画面と API の両方から呼ぶ

- 日付：2026-10-10
- 状態：決定（019 の具体化）

## 背景
019 では「アプリの操作はすべて HTTP API で行う」としていたが、025 で画面は Django テンプレート＋htmx（HTML を返す）と決めた。
これでは、画面が JSON の API を呼ぶのか、ビューが直接処理するのかが曖昧だった（仕様レビュー E3）。

## 決定
- 記録の追加・取り消し・編集、連続記録の計算、実績の判定などの処理は、`services/` にまとめる
- htmx 用のビュー（HTML を返す）と、Django Ninja の API（JSON を返す）は、どちらもサービス層を呼ぶだけの薄い層にする
- 権限チェック（スペースのメンバーかどうか）もサービス層で行う
- v1 では外部向けの API を公開しない。v1.x で MCP と一緒に公開する

## 理由
- 画面と API で処理が重複せず、挙動が食い違わない
- テストはサービス層に対して書けばよいので、テストを書きやすい
- 権限チェックを1か所に集めると、書き忘れによる他人のデータへのアクセス（IDOR）を防ぎやすい

## 影響・トレードオフ
- ビューやスキーマの層が増えるので、ファイル数は少し増える
