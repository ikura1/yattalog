# 044. 写真は β に入れず、反応を見てから決める

- 日付：2026-10-12
- 状態：決定（030 の β の範囲を変更）

## 背景
030 では、β に写真を入れるとしていた。β の入口（038）、書き出し（039）、退会（040）、規約とポリシー（041）、テンプレート（042）、ホーム画面への追加の案内（043）がそろい、β の機能で残っているのは写真だけになった。

## 決定
- **写真は β に入れない。** β で使われ方と要望を見てから、v1 に入れるかどうかを決める
- 写真の仕様（SPEC 5章、決定 005・024・029）は、入れる場合の仕様としてそのまま残す

## 理由
- **β でいちばん確かめたいのは、「やったら1タップ、前回からの日数が分かる」が使われるかどうか。** これは写真がなくても確かめられる
- **知らない人を相手にする最初の公開で、預かるものを増やさない。** 写真には、他人の顔や自宅の中など、文字の記録より繊細な情報が写る。漏れたときの影響が大きい
- **作るものが多い。** 写真を入れると、次がまとめて必要になる
  - 裏で動かす仕組み（#3）。書き出し（039）と退会（040）を「その場で」の方式から作り直す
  - アップロードの検証と作り直し、位置情報の削除、大きさと枚数の制限（SPEC 5章、029）
  - 非公開での配信（期限つきの URL、#4）、HEIC への対応（#7）、書き出しのダウンロードの認証（#19）
  - プライバシーポリシーの改定（委託先に Cloudflare が加わる）
- 費用は理由ではない。β の規模（20人）なら、Cloudflare R2 の無料枠（10GB）にほぼ収まる

## 影響・トレードオフ
- β では、記録に写真を付けられない。メモだけになる
- 写真を前提にした項目（設定の「写真の使用量」、書き出しの `photos/`、退会時の写真の削除）は、写真と一緒に作る
- #3・#4・#7・#19 は、写真を入れると決めたときに着手する
- β の意見の窓口（041）で、写真の要望がどのくらい出るかを見る
