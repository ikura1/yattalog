# 019. API を前提に作り、MCP サーバーは v1.x で公開する（読み取りと記録の追加のみ）

- 日付：2026-10-10
- 状態：決定（027 で具体化）

## 背景
Claude などの AI アシスタントから、「シーツ交換っていつやった？」「ジムやったから記録して」のように使えると便利だという意見が出た。
MCP サーバーを公開すれば、これが実現できる。

## 決定
- v1 では、アプリの操作をすべて HTTP API で行う構成にする。この API は、外部から使われる前提で設計する（認証、スコープ、レート制限）
- MCP サーバーは v1.x で公開する。形式はリモート MCP（Streamable HTTP）、認証は OAuth 2.1 とする
- AI に許可する操作は、読み取りと記録の追加（メモの追記を含む）だけにする

## 理由
- v1 の公開を遅らせずに、後から MCP を薄く足せる
- 同じ API の上に、NFC タグやショートカット用の記録用 URL などの機能も載せられる
- 削除や編集を AI に許可すると、誤操作したときに取り返しがつかない。記録の追加なら、間違えてもアプリで消せる

## 影響・トレードオフ
- v1 の時点から、API の認証とスコープ（read / log）を設計しておく必要がある
- OAuth 2.1 の認可サーバーを用意する必要がある（Django であれば django-oauth-toolkit などを使う）。Google ログインとは別に、Yattalog 自身が認可サーバーになる
- AI から追加された記録は、印を付けて区別できるようにする
- 外部から叩けるので、レート制限と不正利用への対策が必要になる（ステップ5・6で決める）
