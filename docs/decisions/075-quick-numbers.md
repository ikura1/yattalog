# 075. よく使う数字を、押すだけで記録できるボタンにする

- 日付：2026-11-13
- 状態：決定

## 背景
数字の記録（決定 074）を入れたあと、「数字を打つ以外の記録のしかたがあっても面白い。ただ、ごちゃつくのは避けたい」という話が出た。
触れる見本で、打つ・よく使う数字・スライダー・選ぶ・チェックの5つを並べて比べた。

## 決定
まず**よく使う数字**だけを入れる。数字を聞くシートに、これまでによく入れた数字をボタンで並べ、**押すと、その数字でそのまま記録する**。

- 並べるのは、数字を付けた記録の新しいほうから50件のうち、**2回以上**入れた数字。回数の多い順（同じ回数なら、新しく使ったほうが先）に、**4つまで**
- 1回しか入れていない数字は出さない（体重のように毎回ちがう数字では、ボタンが並ばない。前回の数字は、欄に入れてある）
- ボタンは数字の欄の上に置き、欄の名前は「ほかの数字」に変える。よく使う数字がまだなければ、これまでと同じ見た目のまま
- 押したときは、欄の中身ではなく、ボタンの数字を取る。日付やメモを開いて入れていれば、それも一緒に記録する
- 出すのは、新しく記録するシート（タイルを押したとき・長押し）だけ。記録の編集には出さない
- 設定は足さない（イベントの編集は変えない）。取るデータも増えない（ポリシーは変えない）

## 理由
- 設定が要らず、項目も画面も増えない。「ごちゃつかせない」にいちばん合う
- 同じ距離・同じ金額を繰り返すイベントで、打つ手間がなくなる（タイル → ボタンの2タップ。前回と違う数字でも打たなくてよい）
- 押し間違えても、シートの「さっきの記録を取り消す」と記録の編集で直せるので、確かめる一手間は挟まない

## 見送ったもの
- **スライダー**（つらさ・気分などの段階）：イベントごとに範囲の設定が要る。よく使う数字を使ってみてから考える
- **選ぶ・チェック**（種類や、まとめてやったこと）：数字ではない記録になり、データの持ち方と統計を新しく作ることになる。要望が固まってから、別の決定にする
- ボタンを押すと欄に入るだけにする形：［やった！を記録］をもう一度押すことになり、前回の数字を入れておくのと手間が変わらない

## 影響
- `services/numbers.py` の `frequent_values()`、`views/records.py`（`quick` を受け取る）、`_record_sheet.html`
- 古い画面（デプロイの前から開いたままのもの）でも、ボタンは htmx だけで動く。JS は変えていない
