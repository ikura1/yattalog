# 068. 体調は「できごと」として記録し、毎日の気分の記録は持たない

- 日付：2026-11-02
- 状態：決定（SPEC 3.6 のテンプレートに足す）

## 背景
- Yuki さんから「ニコニコカレンダーのような体調・気分の記録をつけたい。このアプリでやるべきか、別アプリか」と相談があった
- ニコニコカレンダーは、毎日1回、気分や体調を点数（顔）で付けるもの。やったログは「前回いつやったか」を1タップで記録するもの

## 決定
- **毎日の気分・体調の点数は、やったログでは持たない。** ほしくなったら、別のアプリとして考える
- その代わり、体調の波を**できごと**として記録できるよう、「からだ」の組にテンプレートを4つ足す
  - 頭痛、痛み止めを飲む、風邪をひく、生理（どれも連続記録はなし）
  - 組の説明に「体調の波も、記録しておくと『前回いつ？』に答えられる」と添える

## 理由
- **コンセプトが逆向き**：毎日付ける記録は、付け忘れが空白として目立ち、「やらなきゃ」を生む。期限も義務もないことが、やったログの持ち味（決定 007）
- **データモデルが合わない**：記録には値の欄がない。点数を持つには、値・1日1件の制約・入力画面・草の色の付け方を、イベントとは別に丸ごと足すことになる
- **商用化の軸がぼやける**：強みは「前回から何日」と、将来の家族での共有。毎日の健康記録は、規約とポリシーの扱いも重くなる（病歴などは要配慮個人情報にあたりうる）
- 一方で「前回の頭痛いつだっけ」「前に風邪ひいたのいつ」は、まさにこのアプリが答える問い。テンプレートを足すだけで、仕組みは変えずに済む

## 影響・トレードオフ
- 「今日は調子がよかった」のような、良い日の記録は残しにくい（メモ欄で補える）
- 生理は、周期の予測などはしない。前回から何日たったかと、平均の間隔が見えるだけ
- 別アプリを作るなら、Django とログインの仕組み、1年の草（`services/review.py`）は使い回せる
