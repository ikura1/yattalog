# 033. 試験運用（α・β）は Cloud Run ＋ Neon（無料プラン）で動かす

- 日付：2026-10-10
- 状態：決定（005 のアプリと DB の部分を置き換え）

## 背景
005 では、アプリと DB を Render（Web Starter ＋ Postgres）で動かすとしていた。この構成では月 $13 前後かかる。
試験運用の段階では、費用をできるだけ抑えたい。

## 決定
- アプリ：**Google Cloud Run**（asia-southeast1・シンガポール）。最小0台・最大2台、リクエストを処理している間だけ課金される
- DB：**Neon**（AWS シンガポール）の無料プラン。接続にはコネクションプーラー（Pooled connection）を使う
- デプロイ：main にマージすると GitHub Actions がイメージを作り、マイグレーション（Cloud Run ジョブ）を実行してからデプロイする。認証はキーを使わない Workload Identity 連携
- 秘密の値（Django の秘密鍵、DB の接続文字列、OAuth のシークレット、管理画面の URL）は Secret Manager に置く
- 写真の保存先は 005 のとおり Cloudflare R2（β で導入）

## 理由
- 自分と知人だけで使う規模なら、Cloud Run の無料枠（CPU 18万秒、リクエスト200万回／月）とNeon の無料プラン（1GB、期限なし）にほぼ収まり、月額はほぼ0円になる
- Neon には東京リージョンがないため、アプリも DB と同じシンガポールに置き、1回の操作で DB と何度もやり取りしても遅くならないようにした
- Google ログインのために、どのみち Google Cloud のプロジェクトを使う

## 影響・トレードオフ
- しばらく使われないと Cloud Run は0台になるので、次の最初のアクセスで1〜3秒ほど待つ（コールドスタート）。Neon も5分使わないと休止する
- 東京から見て、シンガポールまでの往復の遅延（数十ミリ秒）が毎回かかる
- PgBouncer のトランザクションモードに合わせて、Django のサーバー側カーソルを無効にした
- 一般公開して待ち時間が問題になったら、Cloud Run の最小インスタンスを1にするか、常時起動の構成（005 の Render など）に移す。アプリは Docker イメージなので移しやすい
- Render 用の `render.yaml` は削除した
