# 051. β の成功の基準は「続けて使っている人が20人中5人以上」

- 日付：2026-10-14
- 状態：決定（レビュー P3、#9）

## 背景
β を始める前に、何をもって「うまくいった」とするかを決めておく。後から決めると、出た数字に都合のよい基準を置いてしまいやすい。

## 決定
- **基準**：β の枠（先着20人、決定 038）のうち、**続けて使っている人が5人以上**（約25%）
- **「続けて使っている人」**：登録から2週間以上たっていて、直近7日に1回以上記録した人
  - 「記録した」は、記録の日付ではなく、実際に操作した時刻で見る（過去の日付で記録を足した場合も、最近使ったと数える）
  - 登録して2週間たっていない人は、数えない（始めたばかりの勢いを、定着と取り違えないため）
- **見る場所**：管理画面の「利用状況」（`/…/usage/`）。2段階認証を通した管理者だけが見られる（決定 045）
- **出すのは、人数と件数だけ**：登録している人、直近7日に記録した人、続けて使っている人、1人あたりのイベント数（中央値）、記録の総数。だれが、何を、は出さない
- 外部の分析ツールには送らない。自分の DB を数える（ログイン前の画面の流入だけは、Umami で数える。決定 047）
- **見る時期**：β の枠が埋まってから1か月後を目安に、一度判断する

## 届いたとき・届かなかったとき
- **届いた**：中心の価値（1タップで記録し、前回からの経過が分かる）が伝わっている、と見る。v1（一般公開）の準備に進む
- **届かなかった**：使わなくなった理由を調べてから、次を決める。聞く手段は、意見の窓口（決定 041）と、続けている人・やめた人の数の動き

## 理由
- 記録のアプリは、入れた直後は使われやすい。大事なのは、2週間たっても開かれるかどうか
- 20人という小さな母数では、細かい割合に意味がない。「5人」という数で決める
- 5人（4人に1人）は、個人開発の記録アプリとしては、価値が伝わっていると見てよい水準。高すぎる目標（半数など）は、届かなくても失敗と言いにくく、判断の役に立たない

## 影響・トレードオフ
- 20人のうちの5人なので、偶然の振れが大きい。1〜2人の差で結論を変えない
- 「毎月1回やること」だけを記録している人は、使い続けていても、直近7日に記録がなければ数に入らない。Yattalog は間隔の長いことも記録するので、この基準は厳しめに出る。結果を見るときに、割り引いて考える
- 人数だけを出すので、「だれがやめたか」は分からない。理由を聞くには、窓口に頼ることになる
