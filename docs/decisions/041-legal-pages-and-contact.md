# 041. 規約とポリシーをアプリで表示し、問い合わせ先を公開と非公開の2つに分ける

- 日付：2026-10-12
- 状態：決定（#10）

## 背景
β を知らない人に開く（038）前に、利用規約とプライバシーポリシーを読める状態にし、意見や問い合わせを受ける窓口を用意する必要がある。
規約とポリシーは下書き（`docs/legal/*.md`）のままで、運営者名や問い合わせ先が空欄だった。委託先も、以前の構成（Render・Cloudflare）のままだった。

## 決定
- **表示**：`/terms/` と `/privacy/` で表示する。ログインしなくても読める。ログイン画面とメニューからリンクする
- **本文の置き場所**：アプリのテンプレート（`templates/web/legal/`）を正とする。Markdown の下書きは消す
- **運営者**：活動名「ikura1」で表示する。氏名と住所は「請求があったときに遅滞なく開示する」とする
- **問い合わせ先を2つに分ける**
  - ご意見・不具合の報告：**GitHub の Issue**（公開）。メニューに入口を置き、Issue のひな形で「個人情報は書かないで」と断る
  - 個人情報に関わること、そのほか：**非公開の問い合わせフォーム**（Google フォーム）。URL は環境変数（`YATTALOG_CONTACT_URL`、GitHub の Variable `CONTACT_URL`）で渡す。未設定の間は「準備中」と表示する
- **中身を実態に合わせた**
  - 委託先：Google Cloud（アプリ、ログ、ログイン）と Neon（データベース）。保存先はシンガポール
  - まだない機能（写真、シェア、AI 連携、実績）の記述を外した
  - Google Fonts を読み込むときに、IP アドレスなどが Google に送信されることを書いた
  - アクセスログの保存期間を30日とした（Cloud Logging の設定値を確認）
  - 登録できる人数の上限（038）、試験的な提供であること、退会がその場で行われること（040）を書いた
- 制定日は 2026-10-12。登録のときに記録する版（`TERMS_VERSION` / `PRIVACY_VERSION`）も同じ日付にする

## 理由
- 意見や不具合は、Issue で受ければ、そのまま開発の管理に乗せられる。新しい仕組みが要らない
- ただし Issue は誰でも読める。データの開示・削除の請求など、個人情報に関わる問い合わせは受けられない。GitHub のアカウントを持たない人も書けない。そのため、非公開の窓口を別に用意する
- Google フォームは無料で、運営者のメールアドレスを公開せずに済む
- 本文をテンプレートにしたのは、Markdown を表示するためのライブラリを増やさないため。運営者名や問い合わせ先を設定から差し込めるので、書き間違いも減る

## 影響・トレードオフ
- 本文を変えるには、テンプレートを直してデプロイする必要がある
- 非公開のフォームができるまで、問い合わせ先は「準備中」と表示される。**Google の同意画面を「本番」に切り替える前に、必ず用意する**
- 専門家の確認は受けていない。特に、活動名での表示と、氏名・住所を請求時の開示とする扱いは、一般公開の前に確かめたい
- 機能を足して、取得する情報・委託先・保存期間が変わるときは、機能を出す前にポリシーを直す（写真、位置情報 #56、エラー監視 #24 など）
- Google Fonts をやめて、文字のデータをアプリに同梱すれば、Google への送信をなくせる
