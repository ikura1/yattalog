# 063. 実績バッジを入れる（実装の決めごと）

- 日付：2026-10-17
- 状態：決定（020 の実装。SPEC 3.10）

## 背景
実績バッジは v1 の予定（SPEC 7章）だったが、β のあいだに先に入れる。020 と SPEC 3.10 で決めていないことを、ここで決める。

## 決定
- **定義はコードに、解除の記録だけをデータベースに**（`services/achievements.py`、`Achievement` テーブル。`UNIQUE(user, code)`）。データモデルの設計どおり
- **判定する時**：記録（タップ・長押しシート）、記録の編集、イベントの追加（テンプレートからを含む）のあと。新しく解除したものを、その操作の知らせに添える（「やった！ 記録しました　🏅 実績解除：じゅっかい」）。知らせを別に出すと、記録の知らせ（取り消す・メモなど）が消えるため
- **すでに使っている人**：機能が入る前から使っている人（`User.achievements_synced` が False）は、最初の判定で、満たしている実績を**まとめて静かに解除**する（知らせない）。一度に10個以上の知らせが出ないように。これから登録する人は True から始まり、1つずつ知らせる
  - 最初の判定では、過去の記録もさかのぼる（連続記録は、これまでの最高で見る。ひさしぶり・思い出したも、過去の記録から探す）
- **📷 フォトログ**：写真の機能がないので、一覧に出さない（写真を入れるときに足す）
- **📣 シェアデビュー**：シェアは端末で完結するので、「共有する」が終わったとき・「画像を保存する」を押したときに、端末から `/achievements/share/` に知らせて解除する
- **🕰️ 思い出した**：記録の日付が、記録した日（端末のタイムゾーン）より前のとき。記録を過去の日付に直したときも
- **👋 ひさしぶり**：同じイベントの前の記録から、365日以上空けて記録したとき
- **🗂️ コレクター**：アーカイブしたイベントも数える（作ったことには変わりないので）
- **見る場所**：メニューの「実績」（シート）。解除したものは解除した日つき、まだのものはシルエットと条件。「4 / 15」のように数も出す
- **書き出しと退会**：書き出しの `data.json` に、解除した実績を入れる。退会すると消える（ユーザーと一緒に消える）
- **プライバシーポリシー**：保存する情報に「解除した実績」を足し、改定日を 2026年10月17日にした

## セキュリティの見直し（2026-10-17）で決めたこと
- **判定の失敗は、操作の成否に波及させない**。記録はもう保存してあるので、判定で例外が出ても、ログに残して知らせを添えないだけにする（`views/common.new_achievements()`）
- **実績の一覧を開いたときは、判定しない**。機能より前からの人がまだ一度も判定していないときだけ、ここで静かに解除する（GET で書き込むのは、この最初の1回だけ）。一覧も、集計の重い画面の上限（`stats`、1分に60回）で数える
- 同じ実績を同時に2回判定すると、知らせが2回出ることがある。データは一意制約で1件に保たれるので、受け入れる
- 実績は「個人のスペースの記録」を数える前提。家族などとの共有（SPEC 1章）を入れるときは、記録した人ごとに数えるよう直す（記録に作成者 `created_by` はある）
- 最初の判定での「思い出した」は、データベースのタイムゾーン（UTC）の日付で比べるので、日付の境目では取りこぼすことがある（正確さの問題。セキュリティには関係しない）

## 影響・トレードオフ
- 判定は、記録のたびに集計の問い合わせを10回ほどする。どれも索引が効くので、記録の速さに目立った影響はない
- 実績を足すとき（020）は、すでに満たしている人にまとめて解除が起きないよう、`achievements_synced` と同じ考え方で静かに解除するかを決めてから足す
