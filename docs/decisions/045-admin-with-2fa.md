# 045. 管理画面は、決めたメールアドレスと2段階認証で守る

- 日付：2026-10-12
- 状態：決定（レビュー S10、#23）

## 背景
管理画面（Django admin）は、URL を推測しにくくしてあるだけで、管理者も1人もいなかった。β を知らない人に開く（038）と、不正利用への対処（利用の停止、アカウントの削除）のために、管理画面を使えるようにしておきたい。

## 決定
### 入れる人
- 管理者は、**設定（`ADMIN_EMAILS`）にあるメールアドレスの人**だけ。GitHub の Secret で渡す
- 入るには、**Google でログイン**したうえで、**2段階認証**（認証アプリの6桁のコード、TOTP）を通す
- **パスワードは使わない。** Django 標準のパスワードのログイン画面は出さない
- 管理者でない人には、管理画面があることも見せない（404）
- 設定から外すと、2段階認証を通したセッションでも、すぐに入れなくなる
- Django の権限の印（`is_staff` / `is_superuser`）は、設定に合わせて自動でそろえる

### 2段階認証
- はじめて開いたときに、認証アプリに登録する鍵を表示する。正しいコードを入れると、登録が済む
- 登録が済んだあとは、鍵をどの画面にも出さない
- ブラウザごと・ログインごとに、コードが要る。同じコードは2回使えない。続けて間違えると、少しの間、受け付けない
- ライブラリは `django-otp` を使う

### できること
- ユーザーの一覧（メールアドレス、表示名、登録日、最後のログイン、イベント数、記録数）
- 利用の停止（`is_active`）、アカウントの削除（退会と同じ処理。その人のデータもすべて消える）
- **記録やイベントの中身を見る画面は、用意しない**
- ユーザーを作ることはできない（登録は Google ログインからだけ）

### 運営者がデータを見る条件
プライバシーポリシーに、「問い合わせへの対応、障害の調査、不正利用への対処に必要な場合に限り、閲覧することがある」と書いた。

## 理由
- 管理者をメールアドレスで決めるのは、本番でコマンドを打たずに済むため（Cloud Run には、対話的に入る手段がない）。Google が確認済みとしたメールアドレスだけを登録しているので、なりすましはできない
- パスワードを使わないのは、守るべき秘密を増やさないため。「パスワードを保存しない」というポリシーの記述とも合う
- 2段階認証を足すのは、Google アカウントのセッションを奪われただけでは、管理画面に入れないようにするため
- 記録の中身を見る画面を作らないのは、見る手段がなければ、誤って見ることも、奪われて見られることもないため

## 影響・トレードオフ
- 管理者のメールアドレスを Secret に入れる手間がある。Variables に入れると、Actions のログ（公開）に出てしまう
- はじめて開いた人が鍵を登録できるので、**設定に入れたら、早めに自分で登録を済ませる**（登録前に Google のセッションを奪われると、相手に登録されてしまう）
- 認証アプリを入れたスマホをなくすと、データベースを直接直す必要がある（手順は `deploy/README.md`）
- 記録の中身を調べる必要が出たら、Neon のコンソールでデータベースを直接見ることになる。そのときも、ポリシーに書いた条件の範囲に限る
- 管理画面での操作のうち、変更と削除は Django の履歴に残る。見ただけの操作は残らない
