# 052. 費用は月 1,000円まで。超えそうなら、まず新しい登録を止める

- 日付：2026-10-14
- 状態：決定（レビュー P5、#11）

## 背景
試験運用は、無料枠の範囲で動かしている（Cloud Run ＋ Neon、決定 033）。ふだんの費用は、ほぼ0円。
知らない人に開く（決定 038）前に、いくらまでなら出してよいか、超えそうなときにどうするかを決めておく。

## 決定
- **許容する費用は、月 1,000円まで**（ドメイン代などを含めた、Yattalog のための支出の合計）
- **ふだんは、無料枠の中で動かす。** 1,000円は「使い切る予算」ではなく、「ここまでなら慌てない」という上限
- **超えそうになったら、まず新しい登録を止める**
  - GitHub の Variable `MAX_USERS` を、いまの登録人数にして、デプロイする（`YATTALOG_MAX_USERS`）。使っている人には影響がない
  - そのうえで、原因（急に増えた通信、想定外の課金）を調べ、次の手を決める
- **有料の構成や機能を足すときは、先に月額の目安を出して確かめる**（今までどおり）
- 寄付や有料プランは、いまは考えない。考えるのは、一般公開の後に、費用が続けて上限を超えるようになったとき

## 内訳の目安
| 項目 | 月額 |
|---|---|
| Cloud Run、Neon、Artifact Registry、Secret Manager | 0円（無料枠の範囲） |
| GitHub（公開リポジトリの Actions） | 0円 |
| Umami Cloud（無料プラン） | 0円 |
| 独自ドメイン（取る場合。年 2,000〜3,000円ほど） | 約 200〜250円 |
| 合計 | 0〜250円ほど |

残りの枠で選べるもの・選べないもの：
- 選べる：ドメイン、写真を入れた場合の保存（Cloudflare R2。β の規模なら、ほぼ無料枠）
- 選べない：サーバーを1台常に起こしておく設定（待ち時間は減るが、これだけで上限を超える見込み）

## 守りになっているもの
- Cloud Run の台数の上限（最大2台）。通信が急に増えても、費用が青天井にならない
- レート制限（決定 037）と、登録できる人数の上限（決定 038）
- Google Cloud の予算の通知（月 500円で知らせる）。上限の半分で、早めに気づくための合図として残す

## 影響・トレードオフ
- 予算の通知は、知らせるだけで、自動では止まらない。気づいてから手で止める
- 新しい登録を止めると、β の枠が埋まる前に募集が止まることがある
- Google Cloud 以外の支出（ドメインなど）は、予算の通知には出ない。年に一度の支払いを、自分で覚えておく
