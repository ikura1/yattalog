# 029. 写真はサーバーでも検証して作り直し、書き出しの CSV は無害化する

- 日付：2026-10-10
- 状態：決定（024 を補強）

## 背景
024 では、写真の縮小と EXIF の削除を端末で行うとしていた。しかし改造したクライアントからは、位置情報付きの画像や、画像に見せかけた不正なファイルを送れてしまう（仕様レビュー S1）。
また、書き出した CSV を Excel で開くと、`=` などで始まるメモが数式として実行されるおそれがある（仕様レビュー S2）。

## 決定
- **写真**：端末での縮小に加えて、サーバーでも必ず検証して作り直す
  - 受け取るサイズの上限は2MB
  - Pillow で画像として読み込めるかを確認し、画素数にも上限を設ける
  - 長辺1600pxの WebP に作り直して保存する（メタデータはここで必ず消える）
  - Content-Type はサーバーが決める。写真はアプリとは別のドメインから配信する
- **CSV**：`=` `+` `-` `@` タブ・改行で始まるセルは、先頭に `'` を付けて書き出す

## 理由
- 端末から送られてくるものは信用できない。サーバー側での検証が、安全性を担保する唯一の手段になる
- 作り直すことで、位置情報などの個人情報の漏れと、悪意あるファイルの両方を防げる

## 影響・トレードオフ
- 写真の作り直しでサーバーの CPU を使う。1枚あたり数十〜数百ミリ秒程度なので、v1 ではリクエストの中で同期的に処理する。負荷が問題になったらバックグラウンド処理に移す
- CSV のセルの先頭に `'` が付くので、メモの内容がそのままの文字列ではなくなる（data.json には元の文字列のまま入れる）
