# 067. 運用の通知を Discord に送る

- 日付：2026-10-23
- 状態：決定（046 の監視に、知らせる先を足す）

## 背景
監視（決定 046）が困ったことを見つけると、Issue（ラベル `ops`）を開く。Issue の通知は GitHub のメールに混ざり、気づきにくい。運用の知らせだけを受け取る場所がほしかった（Yuki さんだけが見る）。

## 決定
- 知らせる先は **Discord**（Yuki さんだけのサーバーのチャンネル）。無料で履歴が消えず、スマホの通知も確実に届く。Slack の無料プランは 90 日より前のメッセージが見られなくなる
- 送るのは、困ったときだけ
  - Ops report（毎朝）：エラーがあれば、Issue の題名・回数・実行のリンク
  - Uptime（1時間ごと）：`/health` が応答しなかったとき
- 送るのは、公開のリポジトリにもう出ているもの（Issue の題名・回数・リンク）だけ。利用者のデータは送らない
- Webhook の URL は GitHub の Secret `OPS_WEBHOOK_URL` に置き、通知の手順にだけ渡す。未設定なら何もしない。Discord の Webhook 以外の宛先には送らない
- 送るのは `apps/core/ops_notify.py`。通知に失敗しても、監視の実行は失敗にしない（警告だけ出す。URL は出さない）
- `@everyone` などで人を呼ばない（`allowed_mentions` を空にする）

## 理由
- 監視の実行のたびに Issue を見に行かなくても、スマホで気づける
- Webhook の URL は、知っている人が誰でも書き込める秘密の値。ログに出さず、ほかの宛先に送らないようにする

## 影響
- Yuki さんの手作業：Discord にサーバーとチャンネルを作り、Webhook を作って、URL を Secret `OPS_WEBHOOK_URL` に登録する（`docs/operations.md`）
- 費用は増えない
