# 028. 記録は端末で ID を作って送り、画面は先に更新する

- 日付：2026-10-10
- 状態：決定

## 背景
タップで記録したときに通信が失敗した場合の挙動が決まっていなかった。
また、電波が弱いと再送によって二重に記録されるおそれがある（仕様レビュー E4）。

## 決定
- 記録の ID（UUID）は端末で作って送る。サーバーは同じ ID の記録を1件しか作らない（冪等）
- タップしたら、サーバーの返事を待たずにタイルを「今日」に変える（楽観的更新）
- 失敗したら元の表示に戻し、「記録できませんでした ／ もう一度」を出す。「もう一度」は同じ ID で送り直す
- 連続記録や実績の演出は、成功の返事が来てから出す

## 理由
- 1タップで記録するアプリなので、押した瞬間に反応しないと気持ちよくない
- 端末で ID を作れば、再送しても二重記録にならない。将来オフラインでの記録（022）に対応するときも、そのまま使える

## 影響・トレードオフ
- サーバーは、端末から送られてきた ID が他のユーザーの記録と重複していないかを確認する必要がある。重複していたら拒否する
- 演出が少し遅れて出ることがある
