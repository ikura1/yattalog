# 049. Service Worker は、静的ファイルとオフラインの案内だけをしまう

- 日付：2026-10-13
- 状態：決定（レビュー E9、#5。043 で見送ったもの）

## 背景
ホーム画面に追加して使ってもらう（決定 003・043）のに、電波がないときに開くと、ブラウザのエラー画面が出ていた。アプリらしく見えない。
一方、Service Worker で画面をしまっておくと、共用の端末で、前に使った人のデータが見えてしまうおそれがある（レビュー E9）。

## 決定
- Service Worker（`/sw.js`）を入れる。**しまっておくのは、だれが見ても同じものだけ**
  - 静的ファイル（`/static/` の下。CSS・JS・アイコン）
  - オフラインの案内（`/offline/`）
- **ログインした人の画面は、しまわない。** 画面の移動は、必ずネットワークに取りに行く。つながらないときだけ、オフラインの案内を出す
- 記録などの書き込み（GET 以外）と、よそのサイトへの通信には、手を出さない
- オフラインの案内は、利用者ごとの値（名前、CSRF トークンなど）を含まない、独立したページにする
- Service Worker の版は、しまっておくファイルの URL（中身のハッシュ入り）から決める。中身が変われば版が変わり、古いキャッシュは捨てる
- `/sw.js` 自体は、ブラウザにキャッシュさせない（`Cache-Control: no-cache`）
- ログアウト・退会のときは、今までどおり `Clear-Site-Data` で、端末にしまったものと Service Worker を消す

## 理由
- 静的ファイルは、名前に中身のハッシュが入っている。しまってあるものをそのまま使っても、古い中身が出ることがない
- 画面（HTML）をしまわなければ、「ほかの人のデータが見える」「古い記録が出て、最新だと思ってしまう」という問題が、そもそも起きない
- オフラインで記録の一覧を見られるようにするには、データを端末に持つ仕組みと、共用の端末での守りが要る。オフラインでの記録（v1.x）と一緒に考える

## 影響・トレードオフ
- **オフラインでは、記録の一覧は見られない。** 出るのは案内だけ。SPEC 3.12 の「シェルはオフラインでも開ける」は、「案内が出る」までの対応になる
- 2回目からは、静的ファイルを端末から読むので、表示が少し速くなる
- Service Worker が古いまま残ると、直すのが難しい。そのため、やることを少なくし（しまうのは静的ファイルだけ）、新しい版はすぐに切り替わるようにしている
- 開発中（DEBUG）は、URL にハッシュが入らない。版に、ファイルの更新時刻を混ぜている
- iOS では、しばらく使わないと、しまったものが OS に消されることがある。そのときは、次につながったときにしまい直される
