# 053. シェアを β に入れる

- 日付：2026-10-14
- 状態：決定（030 の β の範囲を変更。017 の実装）

## 背景
030 では、シェア（SNS への投稿）を v1（一般公開）に入れるとしていた。
やったことを人に見せられると、続ける張り合いになる。運営者自身が、β の段階からほしいと感じた。β の人の投稿が、そのままアプリの紹介にもなる。

## 決定
- **シェアを β に入れる。** やり方は 017 のとおり（シェア画像を作り、スマホの共有シートに渡す。X には投稿画面を開くリンクも用意する）
- **画像は、端末の中（ブラウザの Canvas）で作る。** サーバーには送らない。記録ごとの公開ページも作らない
- 画像に載せるもの：アイコン、イベント名、「やった！」、見出し、日時、ロゴ。1080×1350px、常にライト配色
- 見出しは、その記録の時点で決める：連続記録 → 同じ日の2回目以降 → 何日ぶりか → はじめての記録
- **メモは、初期状態では載せない。** シェア画面でチェックしたときだけ載せる
- 入口は3つ：連続記録が伸びたときのトースト、イベント詳細（最新の記録）、履歴の各記録
- 共有シートに画像を渡せない環境（パソコンの一部のブラウザなど）では、画像を保存できるようにする
- 投稿文には、ハッシュタグ（#Yattalog）とアプリの URL を付ける

## 写真と実績は、まだ
- 写真を載せる選択肢は、写真の機能と一緒に入れる（決定 044）
- 「はじめてシェアした」の実績は、実績の機能（v1）と一緒に入れる

## 理由
- 画像を端末で作れば、サーバーの費用が増えない。メモなどのデータが、本人が「共有する」を押すまで外に出ない
- 共有シートなら、インスタ、X、LINE など、端末に入っているどのアプリにも渡せる。SNS ごとの連携や審査が要らない
- メモを初めから載せないのは、うっかり人に見せたくないことを投稿しないため

## 影響・トレードオフ
- 絵文字の見た目は、端末によって変わる（#35）。画像に焼き込まれるので、投稿した後は変わらない
- 投稿文の URL は、いまの `run.app` のもの。ドメインを変えると、古い投稿のリンクは古い URL のままになる（#13）。ドメインを取るなら、シェアが広まる前がよい
- β の枠が満員のときは、リンクから来た人は登録できない（ログイン画面に「満員」と出る。決定 038）
- 共有シートを開いた後、実際に投稿されたかどうかは、アプリからは分からない

## 追記（2026-10-14）：リンクを貼ったときの見え方を整えた
投稿文に URL が付くので、X や LINE でリンクのプレビューが出る。何も設定していなかったので、URL だけが出ていた。
- ログイン前の画面に、プレビュー用の情報（タイトル、説明、画像）を入れた
- 画像（1200×630）は、アイコンとロゴと「前にやったの、いつだっけ？」。元は `tools/og.html`、`tools/build_icons.py` で作り直せる
- X では、投稿に画像を付けた場合、リンクのプレビューは出ない（画像が優先される）。プレビューが出るのは、URL だけを貼ったとき


## 追記（2026-10-14）：見出しから「何日ぶり」をやめる
「40日ぶり」は、続けているイベントなら褒め言葉でも、久しぶりにやったイベントでは「サボっていた」と言われているように読める。Yattalog は気軽に、ゆるく使うアプリなので、シェアには、どんなときでも前向きに読めるものだけを載せる（Yuki さんと見本を見比べて決めた）。
- 見出し：連続記録（「🔥 5週連続」）→「はじめての記録」→ 通算の回数（「24回目」）。同じ日の2回目も「この日2回目」ではなく、通算の回数にする
- 連続記録のときは、見出しの下に「通算 24回目」を添える。投稿文は「🔥 5週連続（通算 24回目）」
- 10・30・50・100回目と、そのあと100回ごとは「🎉 10回目」にする（小さなお祝い）
- カードの形（白い紙に「やった！」）は変えない。おしゃれさやおもしろさ（凝った見た目、アプリからのひとこと）は足さない
- アプリの中のタイルの経過時間（「12日前」）は変えない。前回がいつかを見るのが、このアプリの役目なので
- 見送ったもの：数字3つ（ヤマップ風）、大きな数字、スタンプカード、ひとこと入り。スタンプカードは、毎日でないイベントだと、すかすかになる
