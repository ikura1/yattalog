# 038. β は先着20人。登録できる人数に上限を設ける

- 日付：2026-10-12
- 状態：決定（030 の β の対象を変更。#47）

## 背景
030 では、β の対象を「知人10〜20人」としていた。実際には、声をかけられる知人がいないので、知らない人に使ってもらうことになる。
知らない人を相手に、規模と費用を抑えたまま試す方法が要る。

## 決定
- β は**誰でも登録できる**。ただし、**登録できる人数に上限を設ける**。最初は **20人**
- 上限に達したら、新しい登録を止める。登録済みの人は、そのままログインして使える
- 満員のときは、ログイン画面と、Google で認証した後の画面の両方で、その旨を知らせる
- 人数は、有効なユーザー（退会の手続き中でない人）で数える
- 上限は設定（`MAX_USERS`、環境変数 `YATTALOG_MAX_USERS`）で変えられる

## 理由
- **許可制（申し込みを1件ずつ承認する）にしなかった**のは、知らない人を承認する判断材料がなく、手間だけが増えるため。承認待ちの画面や管理画面での操作も作る必要がある
- **Google のテストユーザー方式にしなかった**のは、アドレスを受け取る窓口が要ることと、ログイン時に「確認されていません」という警告が出て、知らない人には不安を与えるため
- 上限があれば、費用（無料枠）と、問題が起きたときの影響範囲を、人数で抑えられる
- データは人ごとに分かれていて（決定 027、#17）、レート制限もある（決定 037）。相手を選ばなくても、ほかの人のデータは守られる

## 影響・トレードオフ
- 相手を選べない。荒らす目的の人が入る可能性はある（レート制限と、人ごとのデータの分離で備える）
- 使わなくなった人が枠を占めたままになる。必要なら上限を上げるか、長く使っていない人の扱いを決める
- 同時に登録が重なると、上限を1〜2人超えることがある（人数を数えてから登録するまでに間があるため）。厳密さは求めない
- **実際に効き始めるのは、Google の同意画面を「本番」に切り替えたとき。**「テスト中」の間は、テストユーザーしかログインできない
- 「本番」に切り替える前に、β の条件（規約とポリシー、退会、書き出し、意見を送る窓口）をそろえる（030 のとおり）
