# 074. 記録に数字を付けられるようにする（合計と推移）

- 日付：2026-11-13
- 状態：決定

## 背景
「ランニングの距離」「体重」「使ったお金」のように、やったことと一緒に数字を残したい、その数字の統計も見たい、という要望があった。これまでは、数字はメモに書くしかなく、合計も推移も出せなかった。
一方で、Yattalog のよさは「1タップで記録できる」ことにある。数字を残さない人・残さないイベントの手間は、増やしたくない。

## 決定
イベントごとに「数字の記録」を選べるようにする。**なし**（これまでどおり）、**合計を見る**（距離・金額・回数など）、**推移を見る**（体重・体温など）の3つ。数字は1つの記録に1つで、単位（8文字まで、自由）をイベントに持つ。

### 記録の流れ
- 数字を聞くイベントは、タイルを押すと**数字を入れる小さなシート**が開く。欄には前回の数字を入れてあり、そのまま［やった！を記録］を押せば、2タップで記録できる
- **数字は空でもよい**（測り忘れた日も、やったことは残せる）
- 日付とメモは「日付やメモも入れる」に畳む。長押しのシートと記録の編集にも、数字の欄を出す
- 数字を聞かないイベントは、これまでどおり1タップ
- 欄には自動でフォーカスしない（スマホでは、キーボードが［やった！を記録］を隠し、前回と同じ数字で済むときの手間が増える）。触ったときは、中身を丸ごと選ぶ（打てば置き換わる）

### 受け取る数字
- 0 以上、整数は9桁まで、小数は3桁まで（`numeric(12, 3)`）。浮動小数ではなく10進で持つ（0.1 を足し続けてもずれない）
- 全角の数字と、桁区切りのカンマは、受け取って直す（「１，２００」→ 1200）
- **負の数は受け取らない**。入れられるようにすると、合計の意味（「これまで 54km」）があいまいになる。気温のような使い方は、要望が出てから考える
- 数字を聞かないイベントに数字が送られてきたら、捨てる
- イベントの「数字の記録」を「なし」に戻しても、付けた数字は消さない（選び直せば、また出る）

### 統計（イベント詳細）
- **合計を見る**：今月・今年・これまでの合計と、今月までの12か月の、月ごとの棒
- **推移を見る**：最新・平均・最小・最大と、折れ線。前回との差も出す。見るのは、数字を付けた記録の新しいほうから30件（増え続けても、グラフが詰まらない）。平均は小数2桁に丸める
- どちらも、数字を付けた記録だけで数える。同じ日に2回あれば、合計は足し、推移は2つの点にする
- 読み上げ向けに、棒には「2026年10月：8.5km」の名前を付け、折れ線には同じ内容の表を添える
- 記録の履歴にも、数字を出す

### そのほか
- 書き出し：`logs.csv` の後ろに「数字」「単位」、`events.csv` の後ろに「数字の記録」「数字の単位」を足す。`data.json` にも入れる。列は後ろに足すだけなので、書き出しの版（1）は変えない
- プライバシーポリシー：取得する情報に「数字」を足し、健康に関する記録の例に「体重」「体温」を足して、2026-11-13 に改定する（体重などは健康に関する数字。扱いは決定 069 と同じ）

## 見送ったもの
- **1つの記録に数字を2つ以上**（距離と時間、最高と最低の血圧など）：入力も統計も一気に複雑になる。まず1つで出して、使われ方を見る
- **タイルに数字を出す**（「今月 42km」など）：タイルは「前にやったのはいつか」を見る場所。詳細で見れば足りる
- **シェアの画像に数字を載せる**：体重やお金は、うっかり外に出したくない数字。載せるなら、メモと同じく「選んだときだけ」にする
- **目標**（月に 50km など）：続けることへの圧にしたくない（決定 068 の考え方と同じ）
- **数字を必ず入れさせる**：測り忘れで記録そのものをやめてしまうほうが損

## 影響・トレードオフ
- 数字を聞くイベントは、記録が1タップから2タップになる。自分で選んだイベントだけなので、受け入れる
- **開いたままの古い画面**（古いスクリプト）は、数字を聞くイベントでも1タップで、数字なしの記録を作る。記録は壊れず、あとから編集で数字を足せる。一覧を読み込み直すと、新しい動きになる
- `Log.value` と `Event.number_kind`・`number_unit` の列が増える（マイグレーション 0006。既存の行は「なし」・数字なし）
