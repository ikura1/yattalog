# 047. アクセス数と流入元は、ログイン前の画面だけ Umami Cloud で数える

- 日付：2026-10-13
- 状態：決定

## 背景
告知（X など）を始めるにあたり、何人が来て、どこから来たか（流入元）を知りたい。
- 費用はほぼ0円のまま（決定 033・046）
- プライバシーポリシーには「広告や行動分析のための外部ツールは使っていない。導入するなら先にポリシーを改定する」と書いている
- ログインした後の画面の URL には、イベントや記録の ID が入る。入力したデータを外に出したくない
- CSP でインラインスクリプトを禁止している。外部のスクリプトは送信先を CSP に足す必要がある
- ドメインはこれから変わる（#13、ikura.dev の検討）。解析の設定がドメインに縛られないほうがよい

## 決定
- **Umami Cloud の無料プラン**（Hobby：月10万イベント、1サイト、6か月保存）を使う
- 読み込むのは**ログインしていない人が見る画面だけ**（ログイン画面、利用規約、プライバシーポリシー）。`/` に来た人はログイン画面に送られるので、入口の数と流入元はここで取れる
  - ログインした後の画面では読み込まない。規約をログイン中に開いた場合も読み込まない
- Cookie は使わない（Umami の既定）。Do Not Track を守る（`data-do-not-track="true"`）
- サイト ID は環境変数 `UMAMI_WEBSITE_ID`（GitHub の Variable `UMAMI_WEBSITE_ID`）。空なら、どの画面でも読み込まず、CSP も広げない
  - あるときだけ CSP に `script-src https://cloud.umami.is`、`connect-src https://gateway.umami.is` を足す
- UTM（`?utm_source=x` など）はそのまま送る。告知の投稿ごとに流入を見分けるため
- プライバシーポリシーの「外部への送信」に Umami を書き、改定日を足す（`PRIVACY_REVISED`、`PRIVACY_VERSION`）

## 理由
| 候補 | 費用 | Cookie | 流入元・UTM | 合わないところ |
|---|---|---|---|---|
| **Umami Cloud** | 無料（10万/月） | なし | あり | 6か月で消える |
| Cloudflare Web Analytics | 無料 | なし | 流入元のみ | 標本抽出。UTM やイベントがない。API が使いにくい |
| Plausible | 月 $9〜 | なし | あり | 有料 |
| GoatCounter | 無料（非商用） | なし | あり | 将来の収益化で条件に触れうる |
| GA4 | 無料 | あり | あり | Cookie と同意の扱いが重く、ポリシーが大きく変わる。スクリプトも重い |
| Cloud Run のログを集計 | 無料 | なし | Referer のみ | ボットと見分けにくく、画面がない |

- Umami はドメインに縛られない（サイトの登録はラベルだけ）。ikura.dev に移っても、Umami の画面でドメインを書き換えるだけで続けて数えられる
- 無料の範囲で流入元と UTM が見られ、Cookie を使わないので同意の画面が要らない
- ログインした後の使われ方（何人が記録しているか）は、外に出さずに DB から数えるほうがよい。必要になったら Ops report（決定 046）に足す

## 影響・トレードオフ
- 広告ブロッカーを使う人は数えられない。自分のドメイン経由で送る方法（プロキシ）はあるが、いまは入れない
- 6か月より前のデータは消える。長く残したくなったら、Umami の書き出しか、有料プランか、自前の Umami を検討する
- ポリシーを改定したので、すでに登録した人（いまは Yuki さんだけ）に改定を知らせる
