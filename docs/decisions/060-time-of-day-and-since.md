# 060. イベント詳細に「そのイベントのくせ」（よくやる曜日・時間帯・日にち）と、はじめての記録からの長さを出す

- 日付：2026-10-14
- 状態：決定（058 の追記の「よくやる曜日」を、ふりかえりからイベント詳細へ移す）

## 背景
統計にあったら面白い指標を挙げ、Yuki さんと「前向きに、ゆるく」読めるものを選んだ。最初は「よくやる曜日」と「よくやる時間帯」をふりかえり画面（全部のイベントをまとめたもの）に置いたが、Yuki さんの想定は**各イベントの詳細**だった。あわせて「月のどの日に多いか」も欲しい、となった。

## 決定
### そのイベントのくせ（イベント詳細、よくやる時期の下）
そのイベントの、これまでの全部の記録で数える。見出しの決め方は「よくやる時期」と同じ（最多の7割以上を挙げる。記録が3回未満なら、まだ出さない）。
- **よくやる曜日**：日曜から土曜の回数を棒グラフで。「よくやるのは 土曜」
- **よくやる時間帯**：朝（4〜11時）・昼（11〜16時）・夕方（16〜19時）・夜（19〜4時）の回数を棒グラフで。**時刻つきの記録だけ**を、記録したときのタイムゾーンの時刻で数える（日付だけの記録は時刻がわからない）。画面にもそう書く
- **よくやる日にち**：1日〜31日のマスを、多い日ほど濃くする（一番多い日を一番濃くして4段階）。見出しは上旬（1〜10日）・中旬（11〜20日）・下旬（21日〜）で「よくやるのは 上旬」
- ふりかえり画面には出さない（ふりかえりは、草とその日の記録だけ）

### はじめての記録から（イベント詳細）
- 統計の下に「はじめての記録 2025年8月3日（1年2か月前）」と出す
- 長さは「今日」「9日前」「10か月前」「1年前」「1年2か月前」のように言う（1か月未満は日、12か月未満は月、それ以上は年と月）

## 追記（2026-10-15）：1枚のカードで切り替える
統計のカードが4枚（よくやる時期・曜日・時間帯・日にち）になり、詳細画面が縦に長くなった（カレンダーと履歴まで遠い）。Yuki さんと比べて、1枚にまとめることにした。
- 「よくやる」の1枚に、時期・曜日・時間帯・日にちの切り替え（タブ）を置く。はじめは「時期」
- 最後に選んだものを、その端末に覚える（`localStorage`、`app.js` の `bindTend()`）。サーバーは「時期」を開いた状態で返す
- 時期の「年ごと／全期間」は、年の切り替えと同じ行に置く
- 見送ったもの：「もっと見る」で畳む（畳んだものは見てもらえなくなりがち）、見出しだけを並べる（グラフを眺める楽しさが減る）

## 見送ったもの
- 一番のペースだった時期、今年いちばんやったこと、はじめてやった数、合計の時間：あとから足せる
- 前回より間隔が延びた・縮んだ、達成率：「サボっている」と読めたり、目標を決めない方針に合わなかったりする
- 日にちの見出しを「1日・15日」のように日単位で言うこと：日ごとだと回数が少なくてぶれる。上旬・中旬・下旬なら落ち着く。29〜31日は、ない月があるので少なめに出る（そのまま）

## 影響・トレードオフ
- 詳細を開くたびに、そのイベントの記録を読んで Python で数える（時間帯はタイムゾーンが記録ごとに違うため）。1つのイベントの記録は多くても数千件なので問題にならない
- 曜日と時間帯の棒グラフは同じ部品（`stats._tendency()`、`presenters.tendency_bars()`、`templates/web/_tendency.html`）で描く。棒の高さは SVG の属性で渡す（CSP で style 属性が使えない）
