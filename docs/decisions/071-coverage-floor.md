# 071. CI でカバレッジを測り、90% を下限にする

- 日付：2026-11-11
- 状態：決定

## 背景
テストは先に書く進め方にしているが、カバレッジは手元でたまに測るだけだった。テストのない処理が増えても、気づく仕組みがなかった。

## 決定
CI の `test` で `pytest --cov` を流し、**全体で 90% を割ったら落とす**。
- 測るのは `apps/` と `config/`。マイグレーションとテスト自身は数えない（テストを入れると、数字が実際より高く出る）
- 設定は `pyproject.toml` の `[tool.coverage.*]`。道具は `pytest-cov`（開発用の依存）
- 入れた時点の値は 94%。下限は、ふだんの変更で引っかからない余裕を残して 90% にした
- 手元では `uv run pytest --cov`。ふだんの `uv run pytest` では測らない（速さを保つ）

## 見送ったもの
- **ファイルごとの下限**：小さなファイルは1行で大きく動くので、直す手間のほうが大きい
- **E2E を足して測る**：サーバーが別スレッドで動くので設定が増える。単体・結合だけで十分に高い
- **外のサービス（Codecov など）に送る**：数字は CI のログで読める。連携先を増やさない

## 影響・トレードオフ
- 低いところは残っている（`apps/core/ops_fetch.py`、`apps/spaces/services.py`、`sortkeys.py` など）。下限は全体の値なので、ここを直すかは別に決める
- 下限は「テストの質」までは見ない。先にテストを書く進め方は、これまでどおり
