# 040. 写真が入るまで、退会はその場で全データを消す

- 日付：2026-10-12
- 状態：決定（021 の作り方を、写真が入るまでの間だけ変える）

## 背景
021 では、退会するとデータをすべて削除するとし、写真ストレージ（R2）の削除も含めて「確実に行い、失敗したら再実行する仕組みが要る」としていた。
そのために、ユーザーには「退会の手続き中」を表す項目（`is_active`、`deletion_requested_at`）を用意してある。

β を知らない人に開く（038）前に、自分のデータを消せるようにしておきたい。一方、写真の機能はまだない。

## 決定
- 写真が入るまでは、退会の操作の中で、**その場で**全データを消す（1つのトランザクション）
  - 個人用スペース（カテゴリ・イベント・記録が一緒に消える）
  - ユーザー（Google との連携情報が一緒に消える）
- 「退会の手続き中」の状態は、いまは使わない（項目は残しておく）
- 確認の画面で、消えるものを示し、先に書き出しを勧め、確認のチェックを入れた場合だけ退会できる（SPEC 3.11.3 のとおり）
- 入口はメニューのいちばん下に、目立たない形で置く
- 退会した後は、ログアウトしてログイン画面に戻し、退会が済んだことを知らせる。端末に残ったデータも消す（`Clear-Site-Data`）

## 理由
- 消すものが DB の中だけなら、1つのトランザクションで確実に消せる。途中で失敗したら、何も消えずに元のまま残る
- 裏で動かす仕組み（#3）が要らないので、費用がかからず、作るものも少ない
- 「退会したのにデータが残っている」時間がない

## 影響・トレードオフ
- 取り消しの猶予がない。押し間違いを防ぐのは、確認のチェックと、書き出しの案内だけ
- セッションは消していない。ユーザーが消えるので、ほかの端末のログインは次のアクセスで無効になる（テストで確認）。残ったセッションの行は、期限切れの掃除で消える
- バックアップ（Neon の履歴）には、保持期間の間だけ残る。期間は #26 でプライバシーポリシーとそろえる
- 写真を入れると、この方式だけでは足りない（R2 の削除は DB のトランザクションに入らない）。そのときに「退会の手続き中」の状態と再実行の仕組みを使う
- 共有機能（v1.x）を入れると、ほかの人と共有しているスペースの扱いを決める必要がある（いまは個人用スペースだけを消す）
- 退会すると、登録できる人数（038）の枠が1つ空く
