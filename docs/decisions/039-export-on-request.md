# 039. 写真が入るまで、書き出しはその場で作って返す

- 日付：2026-10-12
- 状態：決定（021 の作り方を、写真が入るまでの間だけ変える）

## 背景
021 では、書き出しの ZIP を**バックグラウンドで作り**、できあがったらダウンロードリンク（7日間有効、1日1回まで）を出すとしていた。写真を含めると ZIP が大きくなり、作るのに時間がかかるため。
この方式には、バックグラウンド処理の実行環境（#3）と、できあがったファイルの置き場所・期限・ダウンロードの認証（#19）が要る。

β を知らない人に開く（038）前に、自分のデータを持ち出せるようにしておきたい。一方、写真の機能はまだない。

## 決定
- 写真が入るまでは、ZIP を**リクエストの中でその場で作り、そのままダウンロードさせる**
- ファイルはサーバーに残さない。ダウンロードリンクも作らない
- 入口はメニューの「データを書き出す」（POST。ログインと CSRF トークンが必要）
- 回数の上限は、1時間に5回（レート制限、037）
- ZIP の中身は 021・SPEC 3.11.2 のとおり（`logs.csv`、`events.csv`、`data.json`）。`photos/` は写真の機能と一緒に足す
- `data.json` には `format` と `version` を入れ、将来の取り込みや形式の変更に備える

## 理由
- 文字のデータだけなら小さい。毎日10回の記録を10年続けても数万行で、作るのは一瞬で済む
- バックグラウンド処理もファイルの置き場所も要らないので、費用がかからず、作るものも少ない
- ファイルを残さないので、「URL を知っているだけでダウンロードできてしまう」（#19）という問題がそもそも起きない。ダウンロードできるのは、ログインしている本人だけ

## 影響・トレードオフ
- 写真を入れると、この方式は使えなくなる（Cloud Run のレスポンスの大きさと時間に上限がある）。そのときは 021 の方式に移し、#3 と #19 をあわせて決める
- ZIP を作る間、メモリに全データを持つ。記録が極端に多い人が出たら、分けて書き出す方式に変える
- iOS でホーム画面に追加したアプリ（スタンドアロン表示）からのダウンロードは、実機での確認が要る
