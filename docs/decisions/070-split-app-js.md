# 070. 画面のスクリプトを、機能ごとのファイルに分ける

- 日付：2026-11-10
- 状態：決定

## 背景
画面のスクリプトは `static/js/app.js` の1つだけで、930行ほど、関数が95個ほどになっていた。記録、シート、並べ替え、シェアの画像、絵文字の候補、ホーム画面への追加の案内などが1つに入っていて、直したい場所を探しにくい。自分たちの目安（1ファイルは 200〜400行、多くても 800行）も超えていた。

## 決定
ブラウザの標準の仕組み（ES モジュール）で、機能ごとのファイルに分ける。ビルドの道具（バンドラー）は足さない。
- 入口は、これまでと同じ `static/js/app.js`。`<script type="module">` で読み込み、ほかのファイルは入口から `import` する
- 分け方：`dom.js`（共通の小さな道具）、`feedback.js`（手ごたえと知らせ）、`sheet.js`、`theme.js`、`tabs.js`、`home.js`（記録・長押し・編集・並べ替え・スワイプ）、`categories.js`、`emoji.js`、`install.js`、`share.js`、`record-form.js`、`detail.js`、`timezone.js`、`build.js`（新しい版への切り替え）
- 中身の処理は変えていない（置き場所を移しただけ）
- 本番ではファイル名に中身のハッシュが入るので、`import` の先の名前も書き換える。Django に備わっている機能（`support_js_module_import_aggregation`）を、`apps/core/staticfiles.py` の入れ物で有効にする
  - こうすると、**どのファイルを変えても、入口の名前が変わる**。開いたままの画面を新しい版に切り替える仕組み（一覧の `data-app-js` と見比べる）は、入口の名前だけを見ればよいままになる
- 入口が読み込むファイルは、`base.html` の `<link rel="modulepreload">` で、入口と一緒に取りにいかせる（入口を読んでから順に取りにいくと、その往復のぶん、画面が動き出すのが遅れる）

## 書くときの約束
- `import` は1行で、同じ場所のファイルを `import { a, b } from "./x.js";` の形で書く（Django が書き換えられる形。テストが確かめる）
- ファイルを足したら、`base.html` の `modulepreload` にも足す（テストが確かめる）
- 1ファイルは 400行まで（テストが確かめる）
- ほかのファイルの変数は、書き換えられない。状態は持ち主のファイルに置き、関数で読み書きする（例：`theme.js` の `keepTheme()`、`home.js` の `toggleEditing()`）
- 「操作の途中かどうか」（読み込み直しを見送る条件）は、それぞれの機能が `build.js` の `whenBusy()` に足す

## 見送ったもの
- **バンドラー（esbuild など）で1つにまとめる**：Node の道具とビルドの手順が増える。今の大きさ（合計 49KB、圧縮前）では、まとめる得が小さい
- **`<script>` を並べて、共通の入れ物（`window.YL`）でつなぐ**：ファイルごとに名前のハッシュが変わるので、「新しい版かどうか」を入口の名前だけでは見分けられなくなる

## 影響・トレードオフ
- 最初に開いたときに取りにいくファイルが、1つから15個に増える。HTTP/2 で同時に取り、そのあとはブラウザと Service Worker がしまうので、体感の差はほぼない見込み
- Django の `import` の書き換えは、正規表現で行う「試験的」な機能。壊れたら気づけるように、テストで守る
  - 集めたあとのファイルで、読み込む先がすべてハッシュ入りの名前になっている
  - どのファイルを変えても、入口の名前が変わる
  - 集めたあとのファイルを使って、ブラウザで記録できる（E2E）
- 古い画面（1つの `app.js` を読み込み済み）は、新しい一覧を受け取ると、入口の名前が違うので読み込み直す。これまでと同じ動き
