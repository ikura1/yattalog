# 026. すべての記録に「記録した日の日付」を持たせ、後から変えない

- 日付：2026-10-10
- 状態：決定（023 の保存形式を置き換え）

## 背景
023 では、時刻ありの記録を UTC の瞬間として保存し、日付の区切りは「今のタイムゾーン」で計算するとしていた。
しかしこの方式では、ロサンゼルスで 10/9 の夜にやった記録が、日本に戻ってタイムゾーンを切り替えると 10/10 の記録に変わってしまう。
また、時刻ありの記録と時刻なしの記録で保存形式が違うため、集計や連続記録の計算が複雑になる（仕様レビュー E1・E2）。

## 決定
- すべての記録に `local_date`（記録したときのタイムゾーンでの日付）を持たせる。記録した後は変えない
- 時刻ありの記録は、さらに `occurred_at`（UTC）と `timezone`（記録したときのタイムゾーン）を持つ
- 経過日数・連続記録・統計は、`local_date` と「今のタイムゾーンでの今日の日付」で計算する
- 記録を編集して日付や時刻を変えたときは、編集したときのタイムゾーンで `local_date` を決め直す

## 理由
- 「その日にやった」という事実は、後でタイムゾーンを変えても変わるべきではない
- すべての記録が日付を持つので、SQL の `GROUP BY local_date` で集計できる。時刻ありと時刻なしで処理を分ける必要がなくなる
- 日付の計算がタイムゾーン変換に依存しなくなるので、テストが書きやすい

## 影響・トレードオフ
- 023 の「時刻ありの記録は瞬間として保存し、日付は今のタイムゾーンで計算する」は、この決定で置き換える。ユーザーごとにタイムゾーンを持つこと、切り替えの提案は 023 のまま
- タイムゾーンをまたぐ移動の直後は、「今日の日付」と記録の日付の関係がずれることがある（例：日本で 10/10 に記録し、すぐにロサンゼルスに移ると、現地はまだ 10/9）。この場合、経過日数は0未満にならないよう「今日」と表示する
